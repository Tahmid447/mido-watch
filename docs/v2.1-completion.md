# Mido Watch V2.1 — completion and review

Verified 10 October 2026, Japan. Work continues on `codex/mido-watch-v2` and draft PR #1. No merge or production frontend deployment was performed. The existing V2 private-account architecture and original V1 files remain intact.

## Product changes

- Portrait poster library, responsive cinematic home/detail backdrops, readable fallback art, clear focus/touch targets and a two-column mobile library. Home prioritizes tonight’s pick, continue watching, unstarted picks, new recommendations, recently watched titles and a compact taste/release snapshot.
- Quick Interested / Watching / Watched / Skip / Favorite controls. Ordinary priority uses Must Watch (90–100), Strong Pick (75–89), Worth Watching (55–74), Maybe (30–54), Low Priority (0–29); stored numeric values remain available in advanced editing/backups. Saving without changing a label preserves its original numeric value.
- Detail pages keep independent season journals/rankings first-class, with journal notes visible before opening the editor. Recommendations, caveats, source history, runtime/genres, release information and external links are organized around the title.
- Source-specific review tiles/chips retain the original score scale, vote count, verification date and source link. Personal ratings remain in a separate journal. Unverified V1 claims are labeled; no critic scores were scraped or fabricated, and incompatible sources are never averaged.
- Official YouTube trailer dialogs use a validated video identifier, youtube-nocookie, a responsive 16:9 iframe, no autoplay, Escape/backdrop/close controls, focus return and player removal on close. An actual Money Heist Netflix trailer loaded successfully in the owner’s browser. Player lifecycle and mobile behavior are covered separately by isolated browser fixtures.
- Japan provider logos and subscription/rent/buy listings carry visible JustWatch attribution. Automated metadata is distinct from manually verified evidence. TMDb credit and an unmodified approved logo appear in Settings → Credits. No OTT dates were inferred.

## Database migrations

Both additive migrations were applied to the existing dedicated Supabase project; local filenames match the hosted migration ledger:

1. `20261010121748_cinematic_metadata_and_recommendation_bridge.sql`: title metadata JSON (artwork, trailer, runtime, genres, language, season/episode information, candidates, refresh time/state/errors); `watch_entries.in_library`; review/provider provenance and unique evidence keys; recommendation pack/time/runtime/history fields; invoker metadata refresh, pack import and inbox actions; updated library filtering and backward-compatible full backup import.
2. `20261010123511_recommendation_pack_replay_history.sql`: retained pack hashes prevent replaying an older pack over a newer recommendation, preserve the supplied local recommendation date, and attach non-conflicting missing external IDs to matched titles.

All eight existing user tables retain RLS and owner checks. Composite ownership foreign keys and existing import/journal protections remain. New functions are SECURITY INVOKER with an empty search path and authenticated-only execution. Backup format remains version 2 and includes the new fields; V1 and earlier V2 inputs still parse safely.

## TMDb integration and initial enrichment

The owner’s supplied v3 key was verified and stored only in ignored `.env.local` as `TMDB_API_KEY`. A long `TMDB_READ_ACCESS_TOKEN` is also supported; configure one credential. Neither appears in client bundles or commit candidates. Metadata requests are server-only, have bounded timeouts/retries and never log credential-bearing URLs.

Known IDs are used first. Search matches require media type, exact normalized title/alias, and independent year or known-territory evidence. Multiple exact editions require explicit review. Newly added titles attempt enrichment when configured; Friday imports can be enriched through Settings → Metadata in batches of six. ## Recommendation JSON and ChatGPT context

Settings → Sync accepts a pasted/uploaded version-1 Recommendation Pack, validates it with a strict Zod schema, previews new/existing/ambiguous identities and displays review/availability evidence before confirmation. Ambiguous entries require a choice. Confirmation revalidates against the current account, imports atomically under RLS and never writes personal ratings, notes, status, season ranks or taste signals. Pack replay is safe even after newer packs arrive. Previous recommendation context is preserved in history.

New imported titles remain outside the ordinary library until an explicit Add to Interested / Start Watching / Skip action. Dismissal preserves history. Existing accepted/dismissed state survives later packs.

Export for ChatGPT produces compact JSON with meaningful watch reactions, ratings/notes, favorites, skipped/interested/watched titles, independent season progress/ranks and taste/recommendation state. It omits authentication, credentials, database UUIDs, ownership, artwork and bulky metadata. Full backups remain a separate action. See [schema and workflow documentation](recommendation-sync.md) and the downloadable pack template.

There is no unauthenticated ingestion endpoint, frontend service-role key or new scheduling integration.
